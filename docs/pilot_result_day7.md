## 本轮没有测什么

- 没有逐字段数值标注表（A 表未填分数）。
- 没有 core 段耗时中位数/范围。
- 没有双人重叠标注，κ 未测。
- 没有 `persona_consistency` / `omission_naturalness` 的分数分布。

因此，本轮不能写成“标注一致性高”“耗时 X 分钟/条”或任何 pilot 指标；它只是
**规范可用性的定性走查**。

## Day 8a 的补偿动作

1. 正式扩到 60 条前，先取 **5 条**做一次计时校准：
   - 第 1 条 warmup、后 2 条 core、最后 1 条 fatigue；只取 core 中位数。
   - 记录到 `pilot_timing_template.csv` 或 8a 的计时表。
2. 用 core 中位数估 60 条工作量：
   - 若中位数 > 12 分钟/条，60 条明显超过一天，坚持 8a/8b 拆分；
   - 若 5–12 分钟/条，8a 一天可完成建集 + 标注；
   - 若 < 5 分钟/条，检查是否标得太快、证据字段是否被跳过。
3. 双人标注仍按原规则：找不到 B 就 `annotator_B` 留空，报告“单标注者，无 κ”，不凑数。

## 已知限制（写进 Day 8 报告）

- pilot 全 synthetic，不能代表真实聊天分布。
- 本轮是定性走查，不是独立盲标；不能用于估计标注者间一致性。
- “接近预期”不是指标，不能换算成准确率/胜率。
